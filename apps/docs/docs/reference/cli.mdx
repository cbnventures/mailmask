Manage every <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>, <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology>, and setting from the terminal, either through a guided menu or with direct commands you can script.

## Why Use This Command?

1. Opens a guided menu with no arguments so you never need to remember flags for everyday changes.
2. Offers direct commands for managing aliases, destinations, and notifiers, plus `validate`, `generate`, and `deploy`, so you can script everyday changes.
3. Validates the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology> on every change so broken references are caught before they reach Cloudflare.

## Requirements

- **Node.js runtime** — v22 or v24.
- **A Cloudflare API token** — Only needed for `deploy`. See [Deployment](/docs/getting-started/deployment/#api-token-permissions) for the required permissions.

## Usage

<Tabs groupId="install-state">
  <TabItem value="mm" label="mm (installed)" default>

    ```bash
    mm

    # Direct command
    mm alias add -d personal
    ```

  </TabItem>
  <TabItem value="npx" label="npx (no install)">

    ```bash
    # Interactive menu
    npx mailmask

    npx mailmask alias add -d personal
    ```

  </TabItem>

`mailmask` and `mm` are the same command. Inside a clone of the repository, `npm run manage` runs the CLI from source.

## Interactive Menu

Running `mm` with no arguments opens a menu with these sections:

- **Manage Aliases** — Create an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>, list them with their status, or modify one (enable, disable, change expiry, or remove).
- **Manage Destinations** — Add, list, or remove a <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology> inbox.
- **Manage Notifiers** — Add an ntfy topic or a Reverse Proxy for ntfy context, and list or remove any notifier type. Use direct commands to add the other services or send tests.
- **Settings** — Edit the <Terminology title="Mailmask itself, running on your Cloudflare account" to="/docs/reference/terminology#cloudflare-and-deploy">Worker</Terminology> name, <Terminology title="The domain every alias lives on" to="/docs/reference/terminology#cloudflare-and-deploy">base domain</Terminology>, <Terminology title="What happens to mail for an address you never made" to="/docs/reference/terminology#aliases-and-mail-flow">unknown alias action</Terminology>, <Terminology title="alias+anything@ still reaches alias@" to="/docs/reference/terminology#aliases-and-mail-flow">subaddressing</Terminology>, and alias headers.
- **Deploy** — Run the full deploy, with guided <Terminology title="The key that lets the CLI deploy to your account" to="/docs/reference/terminology#cloudflare-and-deploy">API token</Terminology> setup.
- **Exit** — Close the CLI.

Settings have no direct command, so outside the menu they are changed by editing `config.json`. Neither the menu nor the direct commands can change an existing <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>'s label, <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology>, or sender rules, so those also need a hand edit.

## Alias Commands

Commands that take `<address>` expect the part before the `@` in lowercase, exactly as it is stored, such as `velvet-harbor-42` rather than the full address.

### `alias add`

Create an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> and save it to the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology>.

| Flag                       | Description                                                     |
|----------------------------|-----------------------------------------------------------------|
| `-d, --destination <name>` | Destination to forward to. Required.                            |
| `-a, --address <address>`  | Custom address. Without it, one is generated.                   |
| `-s, --style <style>`      | Generated address style: `words` (default) or `random`.         |
| `-l, --label <label>`      | Where you used this alias.                                      |
| `-e, --expires <when>`     | Expiry: `30m`, `12h`, `7d`, `4w`, an ISO date, or `never`.      |
| `--allow <senders>`        | Comma-separated senders allowed to write, such as `*@shop.com`. |
| `--block <senders>`        | Comma-separated senders to refuse.                              |

### `alias list`

Print one line per <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> with its full address, <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology>, status, and label, separated by tabs.

### `alias enable <address>` and `alias disable <address>`

Turn an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> on or off. A disabled <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> refuses all mail but keeps its address reserved.

### `alias expire <address> <when>`

Set when an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> expires. `<when>` accepts `30m`, `12h`, `7d`, `4w`, an ISO date, or `never` to remove the expiry.

A bare date such as `2026-12-31` expires at the start of that day in UTC, so it is recommended to use a full timestamp with an offset instead.

### `alias remove <address>`

Delete an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> from the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology>.

## Destination Commands

### `destination add <name> <email>`

Add a <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology> inbox. Cloudflare emails it a verification link on the next deploy.

The address is saved in lowercase, and the command refuses a name or address that another <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology> already uses.

### `destination list`

Print each <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology> name and address, separated by tabs.

### `destination remove <name>`

Remove a <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology>. The command refuses while any <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> still forwards to it, or while it is the `default_destination`.

## Notifier Commands

Every `add-*` command takes a unique `<name>`. Credentials are saved in `config.json` using the same approach as the existing ntfy token, then copied into the generated Worker bundle on deploy.

### `notifier add-apprise <name>`

Add an Apprise API endpoint. Requires `--url <url>`; add `--urls <urls>` when the API request should specify Apprise notification URLs.

### `notifier add-discord <name>`

Add a Discord incoming webhook. Requires `--webhook-url <url>`.

### `notifier add-email <name>`

Add email delivery through Cloudflare's `send_email` binding. Requires `--from <email>` and `--to <email>`. The sender must use an onboarded Cloudflare Email Sending domain, and the recipient must be verified.

### `notifier add-gotify <name>`

Add a Gotify application. Requires `--url <url>` and `--token <token>`.

### `notifier add-matrix <name>`

Add a Matrix room. Requires `--homeserver-url <url>`, `--room-id <id>`, and `--access-token <token>`.

### `notifier add-ntfy <name>`

Notify an ntfy topic directly. Requires `--server <url>`, `--topic <topic>`, and `--token <tk_...>`.

### `notifier add-reverse-proxy <name>`

Notify a Reverse Proxy for ntfy context. Requires `--url <url>`; add `--token <token>` when the context requires one.

### `notifier add-pushover <name>`

Add Pushover delivery. Requires `--user-key <key>` and `--app-token <token>`.

### `notifier add-slack <name>`

Add a Slack incoming webhook. Requires `--webhook-url <url>`.

### `notifier add-telegram <name>`

Add a Telegram bot destination. Requires `--bot-token <token>` and `--chat-id <id>`.

### `notifier add-webhook <name>`

Add a generic webhook that receives Mailmask's versioned JSON payload. Requires `--url <url>`; add `--token <token>` to send bearer authentication.

### `notifier list`

Print each notifier name and type, separated by tabs.

### `notifier remove <name>`

Remove a notifier.

### `notifier test <name>`

Send Mailmask's standard test notification through the named HTTP notifier. The request has the same service-specific shape and 10-second timeout used by the Worker, and a non-success HTTP status makes the command fail.

An email notifier cannot be sent from this command because the local Node.js process has no access to a deployed Worker's Cloudflare `send_email` binding. The command reports that limit. See [Email notification setup](/docs/features/notifications/#email) for how to verify it after deployment.

## Project Commands

### `validate`

Check the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology> against the schema and its cross-references, and print every problem found. Cross-reference problems only show up once the schema check passes.

### `generate`

Write `wrangler.toml` next to your `config.json`, plus the Worker entry and a copy of the config in `.wrangler/mailmask/` beside it, from the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology> without deploying. Useful for inspecting exactly what the <Terminology title="Mailmask itself, running on your Cloudflare account" to="/docs/reference/terminology#cloudflare-and-deploy">Worker</Terminology> receives.

The generated `wrangler.toml` has no `account_id`, which only `deploy` adds. To run `wrangler deploy` on these files yourself, set the account another way, such as the `CLOUDFLARE_ACCOUNT_ID` environment variable.

### `deploy`

Validate, register destinations, publish the <Terminology title="Mailmask itself, running on your Cloudflare account" to="/docs/reference/terminology#cloudflare-and-deploy">Worker</Terminology>, and point the <Terminology title="Sends every address to Mailmask, so new aliases just work" to="/docs/reference/terminology#cloudflare-and-deploy">catch-all</Terminology> at it. See [Deployment](/docs/getting-started/deployment/#what-deploy-does) for each step.

The direct command reads `CLOUDFLARE_API_TOKEN` from the environment or a `.env` file. It exits with a non-zero code instead of prompting when the token is missing or invalid.

At startup, the CLI loads only the first `.env` file it finds, checking the working directory, then the project root, then the config directory. A token in a later file is ignored, except that `deploy` still reads the config directory's `.env` when no token was loaded.

:::info
Every command that changes the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology> only edits the local file. Run `mm deploy` to apply changes to Cloudflare.
:::
