## Aliases and Mail Flow

| Term                | Also known as        | Definition                                                                                                                                                                                             |
|---------------------|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **alias**           | masked address       | An address on the base domain, such as `velvet-harbor-42@example.com`, that forwards to one destination. It can carry a label, an expiry, and sender rules, and can be disabled without being deleted. |
| **destination**     | forwarding inbox     | A real inbox that aliases forward to. It must be verified in Cloudflare Email Routing before mail can reach it.                                                                                        |
| **subaddressing**   | plus addressing      | Treating `alias+tag@domain` as `alias@domain`, so one alias can be tagged per purpose without creating new ones.                                                                                       |
| **sender rule**     | allow or block entry | An entry in an alias's allow or block list: a full address (`news@shop.com`) or a domain wildcard (`*@shop.com`), matched against the envelope sender.                                                 |
| **refusal**         | —                    | Mail a known alias turns away because it is disabled but still reached, expired, blocked by its sender rules, or missing its destination. The Worker rejects it, so the sender gets a bounce.          |
| **unknown address** | —                    | An address on the base domain that is not an enabled alias. It has no routing rule, so Cloudflare rejects it with `Address does not exist` before it reaches the Worker.                               |

## Cloudflare and Deploy

| Term                         | Also known as         | Definition                                                                                                                                                                                                                       |
|------------------------------|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **base domain**              | email domain          | The domain every alias lives on: a zone's apex, such as `example.com`, or a subdomain set up in Email Routing, such as `mail.example.com`. Mail for any other domain is rejected.                                                |
| **Cloudflare Email Routing** | Email Routing         | The Cloudflare service that receives mail for your domain and hands each alias's mail to the Worker. Adding its MX and SPF records once in the dashboard turns it on.                                                            |
| **routing rule**             | Email Routing rule    | The literal Email Routing rule deploy keeps for each enabled alias, such as `shop@example.com`, that sends its mail to the Worker. Each rule's name starts with `mailmask:` and the Worker name, so deploy only changes its own. |
| **catch-all**                | catch-all rule        | Cloudflare's apex-only rule for addresses without their own rule. Mailmask doesn't use it, and deploy turns off a catch-all that Mailmask 1.0.0 pointed at the Worker.                                                           |
| **custom domain**            | Workers custom domain | The base domain and its `www` host, which deploy attaches to the Worker so the service page has an address. `www` redirects to the base domain.                                                                                  |
| **Worker**                   | Cloudflare Worker     | The Worker deployed to your account that routes each alias's inbound mail. It forwards or rejects mail in memory and never stores it.                                                                                            |
| **API token**                | Cloudflare token      | The Cloudflare credential the CLI deploys with. [Deployment](/docs/getting-started/deployment#api-token-permissions) lists the permission groups it needs on the account and the zone.                                           |
| **config**                   | `config.json`         | The file that holds your destinations, aliases, notifiers, and settings. The CLI reads and writes it, and deploy ships it to the Worker.                                                                                         |

## Notifications

| Term                     | Also known as        | Definition                                                                                                                                                                                                                              |
|--------------------------|----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **notifier**             | notification service | A configured destination for best-effort alerts about known-alias refusals. It translates the alert to a service's API format or takes Mailmask's notification payload directly.                                                        |
| **notification payload** | webhook payload      | Mailmask's versioned JSON contract for generic webhooks and Reverse Proxy for ntfy. Version 1 identifies `app: "mailmask"`, describes the event, and carries the alias, envelope sender, recipient, and refusal reason under `details`. |
