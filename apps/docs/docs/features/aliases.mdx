Hand out a fresh address for every sign-up, then let it expire or switch it off when it has done its job.

## Why Use This Feature?

1. Generates unique addresses on demand so no two sites ever share the same way to reach you.
2. Expires an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> automatically so short-lived sign-ups clean up after themselves.
3. Disables an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> without deleting it so the address stays reserved and can be turned back on later.
4. Labels each <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> so you always know where an address was used.

## Address Styles

| Style  | Example            | When to use it                                       |
|--------|--------------------|------------------------------------------------------|
| Words  | `velvet-harbor-42` | Easy to read aloud or type into a form by hand.      |
| Random | `k7mq2xv9pa`       | Hard to guess, with no words that hint at the owner. |
| Custom | `trial.signup`     | You want a specific, meaningful address.             |

Generated addresses never repeat an existing <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>. Custom addresses use lowercase letters, numbers, dots, hyphens, and underscores.

With direct commands, `-s` picks the generated style, `words` (the default) or `random`, and `-a` sets a custom address instead.

## Usage

```bash
# Memorable two-word address (the default style).
mm alias add -d personal -l "Online shopping"

# Random characters.
mm alias add -d personal -s random -l "Forum account"

# A custom address that expires in 7 days.
mm alias add -d personal -a trial.signup -e 7d -l "Free trial"
```

Every command that changes an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> saves the <Terminology title="The one file that holds every alias and setting" to="/docs/reference/terminology#cloudflare-and-deploy">config</Terminology> and reminds you to run `mm deploy` to apply it.

## Expiry

An expiry accepts a duration or a date:

- **Durations** — `30m`, `12h`, `7d`, or `4w` from now.
- **Dates** — An ISO date or timestamp. A bare date such as `2026-12-31` expires at the start of that day in UTC, so it is recommended to use a full timestamp with an offset, such as `2026-12-31T18:00:00-05:00`.
- **`never`** — Removes an existing expiry.

```bash
# Extend or shorten an existing alias.
mm alias expire trial.signup 30d

# Keep it forever.
mm alias expire trial.signup never
```

The expiry is stored as an exact timestamp in `expires_at`. Mail arriving at or after that moment is a <Terminology title="Mail an alias turns away instead of forwarding" to="/docs/reference/terminology#aliases-and-mail-flow">refusal</Terminology>, and it is never forwarded.

:::info
Expiry is checked when each message arrives, so an <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> stops working on time without a redeploy. You only need to deploy when you set or change the expiry.
:::

## Disabling and Removing

```bash
# Stop accepting mail but keep the address reserved.
mm alias disable velvet-harbor-42

# Start accepting mail again.
mm alias enable velvet-harbor-42

# Delete the alias entirely.
mm alias remove velvet-harbor-42
```

These commands, like `mm alias expire`, take the part before the `@` in lowercase, exactly as it is stored, so `velvet-harbor-42` works but `velvet-harbor-42@example.com` doesn't.

It is recommended to disable rather than remove an address you no longer want. Either way, the next deploy removes the <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>'s <Terminology title="Sends one alias's mail to Mailmask" to="/docs/reference/terminology#cloudflare-and-deploy">routing rule</Terminology>, so Cloudflare rejects its mail with `Address does not exist`.

## Subaddressing

With <Terminology title="alias+anything@ still reaches alias@" to="/docs/reference/terminology#aliases-and-mail-flow">subaddressing</Terminology> on, anything after a `+` is ignored when matching. Mail to `velvet-harbor-42+receipts@example.com` reaches the `velvet-harbor-42` <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology>, and the forwarded `X-Mailmask-Alias` header keeps the full original address so you can see which tag was used.

## Checking Status

`mm alias list` prints each <Terminology title="A stand-in address; mail still lands in your real inbox" to="/docs/reference/terminology#aliases-and-mail-flow">alias</Terminology> with its <Terminology title="Your real inbox, where an alias's mail ends up" to="/docs/reference/terminology#aliases-and-mail-flow">destination</Terminology>, status, and label. The status is `active`, `disabled`, `expired`, or `expires` followed by the timestamp.
